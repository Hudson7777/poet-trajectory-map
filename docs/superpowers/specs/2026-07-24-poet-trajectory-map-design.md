# 文人生命轨迹地图 · 设计 Spec

> 日期：2026-07-24
> 状态：待用户审阅
> 决策依据：见 `docs/decisions.md`（D1-D13，本文件为展开版，如有冲突以本文件为准）

## 1. 项目概述

中国历代文人生命轨迹地图。核心体验：一张水墨手绘大地图，支持朝代切换与人物切换；文人一生行迹按时间线连成轨迹，作品通过「创作地点 + 创作时间」双重锁定标注在地图上；地图之外配生平年表、人物总结、精华名句、作品集四大板块。

准确性是项目的立身之本：生平以正史本传与权威年谱为据，地名坐标以谭其骧《中国历史地图集》与 CHGIS 为据，争议点位明确标注「存疑」，宁缺毋滥。

## 2. 范围

### MVP（本期交付）

- 朝代：仅唐朝一代（宋代及以后在 UI 上灰态展示「敬请期待」）
- 人物：5 人——李白、杜甫、王维、孟浩然、白居易（预留扩展至 8 人）
- 每人生平关键节点 15-25 个、代表作 15-30 首
- 两个页面：总览页 `/poets`、人物页 `/poets/tang/:poetId`

### 扩展路径（预留设计，本期不实现）

- 新朝代：宋（苏轼/辛弃疾/李清照/陆游等）→ 元明清
- 数据量增大后从「构建期内联」迁移到「运行时按人物分包加载」（目录与产物形状已按此设计，零成本切换）

### 明确不做

- 后端 API、数据库、用户系统、评论
- 多人轨迹同屏叠加对比（后续版本再议）
- 精确疆域边界（水墨底图为写意表达，城市点位精确）

## 3. 整体架构

### 技术栈

Vite + React 18 + TypeScript + Tailwind CSS + pnpm；d3-zoom 地图缩放；数据层 YAML 源文件 + 构建期编译校验；无后端，产物为纯静态文件。

项目位置：独立仓库 `~/Desktop/poet-trajectory-map`，技术栈与 personal-website frontend 完全对齐。

### 为将来集成 personal-website 的预留

- 路由约定：全部页面挂在 `/poets` 命名空间
- 主题隔离：全部颜色/字体走 CSS 变量 + Tailwind token，不污染宿主全局样式
- 产物约定：`dist/` 纯静态；数据按人物分包（一人物一 JSON），宿主可直接引用产物或作为 workspace package 引入 `src/` 重新构建

### 目录结构

```
poet-trajectory-map/
├── data/
│   ├── dynasties.yaml            # 朝代注册表
│   ├── geo/<dynasty>/            # 每朝：basemap.svg（水墨手绘底图）+ cities.yaml（地名坐标表）
│   └── poets/<dynasty>/          # 每朝：一人物一 YAML 源文件
├── scripts/build-data.ts         # YAML → JSON 编译 + schema 校验
├── public/data/                  # 构建产物（一人物一 JSON）
└── src/
    ├── components/map/           # InkMap（SVG 底图 + d3-zoom）、Trajectory、CityMarker、WorkMarker
    ├── components/sections/      # Timeline、Works、Summary、Quotes 四大板块
    ├── themes/                   # base.css、tang.css、poets/*.ts、motifs/（意象 SVG）、easter-eggs/
    ├── data/                     # 生成的 TS 类型 + 数据索引
    └── pages/                    # /poets 总览、/poets/tang/:poetId 人物页
```

### 数据流

YAML 源文件 → `pnpm build:data` 校验编译 → `public/data/*.json` → 前端构建期内联（默认人物=李白）+ 运行时 fetch（其余人物，本地静态服务下接近瞬时）。

## 4. 数据模型

### 朝代注册表（data/dynasties.yaml）

朝代为一等公民。新增朝代 = 注册表加一行 + 新增 `data/geo/<dynasty>/` 与 `data/poets/<dynasty>/` 两个目录，代码零改动。

```yaml
- id: tang
  name: 唐
  era: [618, 907]
  divisionName: 道                 # 唐=道，宋=路，元=行省，明=布政使司
  basemap: geo/tang/basemap.svg
  cities: geo/tang/cities.yaml
  projection: { lon0: 72, lat0: 54.5, s: 25, sy: 29 }   # 每朝独立投影常量，渲染层数据驱动
  viewBox: "0 0 1650 1130"
```

### 人物源文件（data/poets/tang/libai.yaml）

```yaml
id: libai
name: 李白
courtesyName: 太白
dynasty: tang
birth: { year: 701, place: 碎叶 }
death: { year: 762, place: 当涂 }
theme: libai
summary:
  review: 评传式总结（据正史提炼，Claude 撰写，用户审）
  stats: { cities: 18, works: 存诗约千首, topOffice: 翰林供奉, age: 61 }
stops:                             # 生平关键节点 15-25 个，按年份升序
  - year: 742
    city: 长安
    event: 供奉翰林
    role: 翰林供奉                 # 当时身份/官职
    eraName: 天宝元年              # 可选，仅展示用
    works: [清平调三首]
    source: 《旧唐书·文苑传》      # 必填，出处
  - year: 758
    city: 夜郎
    event: 长流夜郎
    role: 逐臣
    source: 《新唐书·李白传》
    uncertain: 夜郎确切位置有三说，取桐梓说    # 存疑标注：UI 显示「存疑」徽记
works:                             # 代表作 15-30 首
  - title: 静夜思
    year: 726
    city: 扬州
    genre: 诗                      # 诗|词|文|赋|曲，唐默认「诗」
    text: 床前明月光……             # 全文
    background: 创作背景与系年系地依据
    famous: [床前明月光, 疑是地上霜]
    source: 《李太白全集》卷六
```

### 城市坐标表（data/geo/tang/cities.yaml）

唐代地名 → { 今名, 经度, 纬度, 所属道 }。stop/work 只写地名，坐标考证集中在坐标表一处。地名作用域为本朝——同一地点在不同朝代是不同条目（唐·钱塘/宋·临安/今·杭州），天然隔离。

### 构建期校验（不过则构建失败）

- stops 按年份升序；所有 city 必须注册于本朝坐标表
- work.year ∈ 人物生卒年区间 且 ∈ 朝代 era 区间
- work.famous 必须是 work.text 的子串
- poet 文件必须位于 `poets/<dynasty>/` 且 dynasty 已注册
- 主题文件六类 token 必填（TS 强制）；motifs/彩蛋引用的 SVG 必须存在

## 5. 底图与地图交互

- 底图：纯手绘水墨风 SVG（疆域/州界写意，不追求几何精确；**城市点位按精确经纬度考证后投影放置**），每朝一份 basemap.svg
- 交互：自绘 SVG + d3-zoom 缩放/拖拽；城市标签与作品标记随缩放级别显隐；不用 Leaflet
- 参考 mockup（已验证渲染）：`~/Documents/claude-outputs/文人轨迹地图-方案B-手绘水墨风.html`（正式底图需在此风格基础上重新手绘，mockup 几何为现代国界占位，不代表最终形态）

## 6. 页面结构与交互

### 总览页 /poets

- 顶部：朝代切换器（唐可选，其余灰态）
- 主体：人物卷轴卡片墙（画像/印章意象 + 姓名 + 生卒年 + 一句代表作，按各人主题色渲染）
- 底部：项目说明（数据来源与考证原则、存疑标注说明）

### 人物页 /poets/tang/:poetId（纵向四段式）

1. **Hero 全屏水墨地图**：轨迹线按时序连接；城市朱砂印点（hover 显示年份+事件）；作品卷轴标记（点开作品卡）；左上题字 + 生卒年；右上返回朝代/切换人物下拉；**底部可拖动时间轴**——拖动时轨迹渐进点亮、地图平移缩放到当年位置、当年作品标记浮现
2. **生平年表**（竖向时间轴）：与地图双向联动——hover 年份地图高亮对应城市，点击年份地图 flyTo
3. **人物总结 + 生涯数字**：评传文字 + 四个大数字（行迹城市数/存世作品数/仕途最高/寿命）
4. **精华名句 + 作品集**：3-5 句名句竖排书法；作品卡片按时期分段，点开看全文 + 创作背景 + 地图定位

### 通用交互规则

- 存疑点位：空心印点 + 「存疑」小字，hover 说明争议与主流说法
- 切换人物：页面不刷新，数据 + 主题色平滑过渡（色调流转动画），URL 同步可分享
- 移动端：地图可缩放，时间轴简化为横向滑动条，四板块纵向堆叠

## 7. 主题系统与水墨质感

### 三层架构

全局水墨基底 `base.css` → 朝代基底 `tang.css` → 个人主题 `themes/poets/*.ts`，逐层覆盖，全部 CSS 变量生效。切换人物时在 `<html>` 上换 `data-poet` 属性，配合 0.6s transition 实现整页色调流转。

个人主题七类 token（TS 强制必填）：accent / accentSoft / inkTone / paperTone / seal / motifs / calligraphy。

### 书法字体

引入 Google Fonts 开源书法字体（unicode-range 分包加载），按人物气质分配：刘健毛草（草书）=李白；龙藏（隶意）=杜甫；马善政（楷书）=王维；志莽行书（行书）=孟浩然/白居易。用于题字/名句/年份数字；正文宋体系；fallback 系统楷体栈；名句竖排（writing-mode: vertical-rl）。

### 水墨质感

SVG 纸纹滤镜（噪点+纤维感）；板块分隔带为淡墨山水横卷且每人不同（李白=长江月影、杜甫=秦陇烽台、王维=辋川青绿、孟浩然=江南春山、白居易=钱塘春景）；卡片"托裱"效果（宣纸卡+细褐绫边+微阴影）；生涯数字衬淡墨晕染；背景层极淡山水 parallax（纯 transform）。

### 人物主题（必须契合生平与作品风格，配色/意象写明出处）

| 人物 | 主题 | 色 | 意象（出处） |
|---|---|---|---|
| 李白 | 谪仙·明月 | 月白+青莲黛+酒金 | 月（举杯邀明月）、酒樽（将进酒）、青莲（号青莲居士）、剑（仗剑去国） |
| 杜甫 | 诗史·烽燧 | 赭石+烽烟灰+暗朱 | 烽燧（安史之乱）、茅屋（茅屋为秋风所破歌）、孤舟（晚年漂泊） |
| 王维 | 辋川·空山 | 青绿+竹青+墨蓝 | 竹（独坐幽篁里）、空山（空山新雨后）、琴（弹琴复长啸） |
| 孟浩然 | 鹿门·春晓 | 春泥褐+新绿+淡粉 | 鹿门山（隐居地）、桃花（春晓）、舟（欲济无舟楫） |
| 白居易 | 江南·香山 | 杏花粉+春水绿+暖白 | 杏花（乱花渐欲迷人眼）、琵琶（琵琶行）、香炉峰（号香山居士） |

### 彩蛋系统

每人 3-5 个专属彩蛋，配置驱动（`theme.easterEggs`），组件化 opt-in，主题文件只声明启用项与挂载节点。已确认示例：

- 李白：当涂江面「水中捉月」月影随鼠标轻晃；轨迹线洒金渐变；地图西缘「碎叶」箭头题「西域万里」；时间轴走到 742 年浮现「翰林供奉」朱印
- 杜甫：755 年起轨迹线变烽烟质感（安史之乱分界）；成都草堂节点 hover 掀顶；地图西边画西岭雪山（窗含西岭千秋雪）
- 王维：辋川竹影微风摇曳；全页留白显著多于他人（禅意）；点击空山涟漪荡开
- 孟浩然：名句区「春眠不觉晓」花瓣缓落；一生布衣，轨迹节点刻意做「疏」；洞庭湖「八月湖水平」水波
- 白居易：浔阳江头夜泊月色中飘出琵琶音符；晚年轨迹末端放缓收尾于洛阳香炉峰；「离离原上草」草叶摆动

主题/意象的具体视觉设计阶段调用 frontend-design skill 做审美评审。

## 8. 数据考证流程

### 资料源三级

- **一级（史实依据）**：正史本传（《旧唐书》《新唐书》，原文经 ctext.org 核对）+ 权威年谱/系年（詹瑛《李白诗文系年》、郁贤皓《李太白全集校注》、仇兆鳌《杜诗详注》、赵殿成《王右丞集笺注》、陈铁民《王维年谱》、朱金城《白居易集笺校》《白居易年谱》）
- **二级（地理依据）**：谭其骧《中国历史地图集》（唐代分册）、CBDB、CHGIS——唐代地名↔今地对照与坐标复核
- **三级（禁作依据）**：百度百科、公众号、无出处年表——仅可用来找线索

### 每人三轮工作制

1. **骨架轮**：正史本传 + 年谱 → 生平节点骨架（年份/地点/事件/官职），逐条记出处
2. **作品轮**：代表作逐首系年系地写依据；无法定位到城市的作品不收（宁缺毋滥）
3. **校验轮**：时间线自洽检查（不可能同年瞬移两地、行程速度合理性）、坐标对照谭图复核、生成 YAML 跑构建校验

### 出处与校对

- stop/work 的 `source` 字段必填；`uncertain` 写明各方说法
- 每人 YAML 产出后输出一份校对表（年份/地点/事件/出处）给用户抽查；有问题打回重做该人物，不进入下一个
- 评传式总结由 Claude 基于正史撰写，随校对表送审；传说类内容必须标明「传说」

### 检索纪律

网络检索一律 super-search（本环境 WebSearch 始终返回空，禁用）；读资料全文用 article-reader；学城文献用 citadel。此纪律写入所有数据类 subagent 的 prompt 原文。

## 9. 错误处理与边界

- 数据错误是第一优先级：构建期 schema 校验拦截结构性错误（未注册地名、年份越界、名句不在原文）；内容性错误靠考证流程与人工校对拦截（见第 8 节）
- 人物 JSON 加载失败：人物页降级为文字版年表 + 作品集（无地图），并提示重试
- 书法字体加载失败：fallback 系统楷体栈，版式不崩（字族 metric 差异通过预留行高吸收）
- basemap.svg 缺失：该朝代在总览页灰态不可选，不影响其他朝代

## 10. 测试与验证策略

- **数据层**（重点）：`scripts/build-data.ts` 的校验规则有单元测试（正反用例）；五人数据全部通过构建校验 + 用户校对表抽查
- **组件层**：Trajectory 轨迹绘制（按年份过滤）、Timeline 联动（hover/click 状态同步）、主题切换（token 覆盖与色调过渡）有组件测试（Vitest + Testing Library）
- **视觉验收**：五个人物页逐一 playwright 截图走查（水墨渲染、存疑标识、彩蛋触发、移动端布局），截图存档供用户过目
- **准确性验收**：每位人物一份「年份/地点/事件/出处」校对表，用户抽查通过后该人物才算完成
